# EduMatrix 最终提交材料阶段规范

## 适用范围

当前项目处于比赛最终提交材料准备阶段。本文件适用于作品设计实现方案、作品介绍、系统部署说明、测试说明、测试数据、评委运行手册、演示材料和最终提交包的审计与生成。

旧版 F0-F10 重构任务、原子任务协议、逐原子账本、旧 checkpoint、旧恢复包和旧阶段状态不再作为当前提交阶段的执行门禁。上一版本提交材料、旧版技术文档、旧版 PPT、旧版测试报告和旧压缩包不得作为当前事实来源。

## 当前工作流程

所有提交材料工作按以下流程执行：

```text
官方赛题要求
→ 当前源码和证据审计
→ 当前运行与测试验证
→ 材料编写
→ 测试数据整理
→ 文档格式检查
→ 敏感信息、旧内容和许可证扫描
→ 视频与报名表接入
→ 最终压缩包检查
```

每轮工作只需记录：

- 本轮目标；
- 使用的当前文件和证据；
- 生成或修改的文件；
- 验证命令及实际结果；
- 未验证能力、外部依赖和限制。

## 当前事实和证据规则

- 优先使用当前赛题 PDF、当前源码、当前配置和当前重新运行的结果。
- [TECH-DOC-CODE-MAP-01.md](../outputs/原系统融合重构执行/evidence/custom_tasks/TECH-DOC-CODE-MAP-01/TECH-DOC-CODE-MAP-01.md) 可作为当前技术文档的代码索引，但不能单独证明运行结果或比赛指标。
- 代码存在只能证明源码结构存在。
- 单元测试只能证明被测试的行为。
- 浏览器截图只能证明截图时的页面状态和操作结果。
- 历史测试结果必须标注日期和版本，不能无条件写成当前结果。
- deterministic 模式不能描述为真实外部大模型效果。
- 模型自评、自动评测或合成数据不能描述为独立人工验证或真实用户实验。
- 幻觉率、资源难度适配准确率和核心知识点覆盖率必须同时说明数据集、分母、计算方法、运行版本和复核责任；缺少这些信息时写“未正式测量”或“待独立复核”。
- 完整 Prover/Challenger/Judge 辩论只能在实际执行和有证据时声明；普通聊天不能笼统宣称每次都执行完整辩论。
- 作品名称、赛题编号、学校、申报人和联系电话必须与报名表及官方填报内容一致。

## 材料内容要求

提交材料应覆盖：

- 作品设计与实现方案；
- 作品介绍；
- 多智能体角色、协同流程和决策机制；
- 个性化资源生成和学习反馈闭环；
- 领域知识库、RAG、来源和证据链；
- 系统部署和评委复现步骤；
- 单元、集成、API、安全和浏览器测试；
- 至少一个垂直领域知识库切片；
- 至少两组差异化学习者样例，建议准备三组；
- 每组画像的输入、Agent 中间过程、最终资源和反馈后决策；
- 测试数据说明、失败案例和指标计算方法；
- 数据合规、隐私、许可证和外部服务边界。

## 安全、隐私和许可证

- 不得提交 `.env`、API Key、JWT 密钥、真实密码或私有推理内容。
- 不得提交真实用户姓名、手机号、邮箱、学习记录或未脱敏交互日志。
- 不得把运行数据库、WAL/SHM、测试缓存、虚拟环境或 `node_modules` 放入最终包，除非明确属于必要且已审计的可执行材料。
- 合成或脱敏数据必须明确标注，不能包装成真实用户数据。
- 第三方课程、文档、图片、代码和数据必须保留来源、许可证和再分发边界；无法确认授权的素材不得进入提交包。
- 外部模型、联网搜索、Docker、PDF 导出和其他可选服务必须说明所需环境和未验证边界。

## 修改和测试边界

- 文档和测试数据优先写入新的独立提交材料目录，不覆盖旧材料。
- 只有用户明确要求时才修改产品代码、数据库、权限逻辑或课程数据。
- 运行测试、构建和浏览器验证时优先使用隔离数据库或临时目录，避免污染正式运行数据。
- 测试失败、环境缺失、外部服务不可用和未完成的人工复核必须如实记录，不得通过跳过、弱化或伪造结果使任务变绿。
- 每次生成材料后检查旧题名、旧包名、旧日期、敏感信息、断链、文件缺失和材料之间的版本不一致。
- 保留工作树中已有的用户或其他任务修改，不使用破坏性命令清理或回退无关变更。
- 未经用户明确要求，不执行 `git add`、`commit`、`push`、`merge`、`rebase` 或历史改写。

## 生成和交付检查

最终提交包生成前必须确认：

1. 文档、源码、测试数据、视频和报名表对应同一当前版本。
2. 报名表为报名系统审核通过且已盖章的扫描件。
3. 演示视频不超过 10 分钟，并展示画像输入、Agent 协同过程和个性化资源生成闭环。
4. 源码、部署说明、测试入口和知识库切片能够相互对应。
5. 至少两组差异化画像材料完整，评分准备按三组画像执行。
6. 测试命令、实际结果、限制和外部依赖已记录。
7. 压缩包名称严格使用学校、申报人、作品名称和联系电话。
8. 最终压缩包不含密钥、真实隐私数据、运行数据库和未授权材料。
